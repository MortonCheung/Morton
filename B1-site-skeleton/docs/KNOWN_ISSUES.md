# 已知问题 — B1

按“是否影响验收/阅读”排序。已确认修复的问题列在最后，便于复核。

## A. 影响观感、但功能可用

1. **章节衔接期字母会短暂压到下一章左上角文案。**
   R→T、T→O2 的 sticky 交接处（约 100vh 滚动）里，上一章的字母仍保持活动姿态，而下一章正文已随面板进入。文字在 3D 之上仍可读，但叠压关系不够干净。
   影响视口：1366 / 1440 / 1024 更明显。移动端因字母为水印（tone 0.5）影响较小。
   后续方案：让字母在上一章 `p > 0.85` 时预退到水印位置，或把字母的下一次前移延后到下一章 `p > 0.15`。

2. **O 的实体圆环与 DOM 轨道圆环不是像素级同心。**
   在 1440 下水平偏差约几像素到十几像素（透视 + 挤压深度 + 字形 overshoot 共同造成），视觉上可读为“字形套在轨道里”，但严格对齐还差一次标定。已用 DOM anchor 投影保证大方向正确；若要像素级对齐，需要按字形包围盒中心而非 bbox 中心投影，并单独为 O 章调一个偏移。

3. **画廊中段的卡片会在视口左右边缘被裁切。**
   这是横向轨道的**有意行为**（画廊延续感），两侧有 18px `mask-image` 渐隐，首帧所有轨道从 0 开始、第一张卡完整可见。若评审认为仍像 bug，可改为“每屏按卡宽吸附对齐”。

4. **移动端（≤820px）画廊每屏只显示约 1.2 张卡。**
   8 件作品仍全部可达（3 条轨道都渲染），但浏览效率低于桌面。后续可加轨道吸附或改为移动端纵向列表。

5. **作品占位视觉是生成的抽象构图，不是真实项目图。**
   这是有意的内容真实性约束；替换为真实图片时只需在 `ProjectVisual` 处接入图片并保留占位标签逻辑。
